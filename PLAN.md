# Социометрия студсовета. План v1

Сайт на FastAPI. Полноценный фронт пока не делаем: API и простые HTML-формы на Jinja. Хранилище на старте два JSON-файла, шифрование и «серьёзную» БД добавим, когда скажете.

## 1. Роли и кто что видит

| Роль | Как входит | Что видит |
|---|---|---|
| Участник (около 60 человек) | регистрация: почта + ФИО, без подтверждения почты (принято «на доверии») | свои вопросы, своё прохождение, свой личный отчёт (PDF по почте) |
| Руководство | один общий аккаунт | только список «кто прошёл / не прошёл» (без ответов, нужен чтобы напоминать); ответы на частные вопросы руководства с именами |
| Аналитик | полный доступ, один человек, не привязан к студсовету | всё, включая закрытую БД; проверяет данные; запускает расчёт; пишет текст общего отчёта; рассылает личные отчёты |
| Публика / студсовет | без входа | общий отчёт (безлично) |

Матрица доступа к данным:

| Данные | Участник | Руководство | Аналитик |
|---|---|---|---|
| Открытая БД: участники, периоды, частные вопросы и их именные ответы | свои ответы | да | да |
| Закрытая БД: анонимные ответы на постоянные вопросы | нет | нет | да |
| Список «кто прошёл» | нет | да | да |
| Личный отчёт | свой | нет | да |
| Общий отчёт | да | да | да |

## 2. Вопросы

### Постоянные (9, анонимные, зашиты в БД)

| № | Критерий | Знак | Текст |
|---|---|---|---|
| 1 | Досуг | + | Кого бы вы позвали на день рождения или другой праздник (вечеринку)? |
| 2 | Досуг | − | Кого бы вы НЕ стали звать на день рождения или праздник? |
| 3 | Организаторские способности | + | Кто справился бы с ролью руководителя мероприятия/проекта? |
| 4 | Организаторские способности | − | Кто НЕ справился бы с ролью руководителя мероприятия/проекта? |
| 5 | Совместная работа | + | С кем бы вы хотели организовать мероприятия? |
| 6 | Совместная работа | − | С кем бы вы НЕ хотели организовывать мероприятия? |
| 7 | Доверие | + | К кому бы вы обратились в трудной жизненной ситуации? |
| 8 | Доверие | − | К кому бы вы НЕ обратились в трудной жизненной ситуации? |
| 9 | Референтометрия | нет знака | Чьи индивидуальные ответы вам было бы интересно увидеть? |

Вопрос 9 считается как выбор людей, но не входит в групповые индексы и графики; нужен для личных отчётов (5-й критерий). Порядок: пары подряд, плюс перед минусом; вопрос 9 последний.

Нумерацию и порядок критериев в отчёте можно оставить как в вашем примере PDF: Совместная работа, Организаторские способности, Доверие, Досуг, Референтометрия.

### Частные
Создаёт руководство или аналитик вручную (форма). Ответы с именами, в открытой БД. Типы ответа: выбор людей и свободный текст. Тематические сводки по ним попадают в общий отчёт безлично.

## 3. Правила формы

1. Поиск по ФИ в списке.
2. Лимита выбора нет, «Никто» разрешён.
3. Человека нельзя выбрать самого себя.
4. В вопросе пары (+/−) тот, кто уже выбран в парном вопросе, показывается серым с подписью «уже выбран в вопросе N». Выбрать всё равно можно, но с предупреждением.
5. Если человек выбран в обоих вопросах пары, считаются оба выбора, а в закрытой БД такая пара помечается флагом `conflict` для аналитика. При массовых противоречиях у одного респондента аналитик может исключить его ответ по этой паре.
6. Если выбраны все или почти все во всех вопросах, ответ помечается подозрительным (для аналитика).
7. Если во всех вопросах «Никто», участнику присваивается внутренний статус «Индивидуалист».
8. Черновик сохраняется по ходу, после «Отправить» правка закрыта.

## 4. Данные (JSON)

`open_db.json` (видят руководство и аналитик)
```
members      [{id, full_name, email, registered_at, joined_at?, role}]
periods      [{id, title, status: draft|open|closed, opens_at, closes_at}]
questions    [{id, kind: permanent|custom, text, answer_type, polarity, criterion,
               pair_id, is_anonymous, position}]
period_questions [{period_id, question_id, position}]
completions  [{period_id, member_id, submitted_at}]          # только факт прохождения
custom_answers [{period_id, question_id, member_id, targets|text}]   # именные
```
`closed_db.json` (только аналитик)
```
submissions  [{period_id, member_id, status, submitted_at}]
answers      [{period_id, question_id, member_id, target_id}]
conflicts    [{period_id, member_id, pair_id, target_id}]
flags        [{period_id, member_id, kind}]                  # suspicious, individualist
```
Слой хранилища делаем интерфейсом (`Repository`), чтобы потом заменить JSON на SQL без переписывания логики. Запись атомарная (временный файл и переименование) плюс блокировка на файл.

## 5. Расчёт (по вашему отчёту, проверено на цифрах PDF)

Обозначения: `n` число участников периода, `K = 5` критериев (с референтометрией).

Подтверждено:
- Индекс статуса `S_i = (все полученные выборы по всем K критериям, плюс и минус одинаково) / (K · (n−1))`. Проверка: 141 / (5·67) = 0,42.
- Индекс экспансивности `E_i = (все сделанные выборы) / (K · (n−1))`. Проверка: 180 / (5·67) = 0,54.
- Взаимность группы `Gg = (число взаимных положительных пар) / (n(n−1)/2)`. Проверка: март 2026, 27,4%.
- Конфликтность `Y` по тому же принципу для взаимных отрицательных пар. Проверка: 0,9%.
- Место участника по `S`, показывается диапазоном «11–20».

Не подтверждено, нужна формула: `Ag` (экспансивность группы) и `U` (референтность группы). Берём естественные варианты (среднее E по группе; доля взаимных выборов в вопросе 9) и сверяем с вашими графиками.

Противоречия (+ и − одному человеку): оба выбора идут в `S` и `E`, пара помечена флагом.

## 6. Защита чисел в личном отчёте

Выборы, которые человек сделал сам, показываются точно. Всё, что позволяет вычислить чужие ответы, скрыто:
- сколько людей выбрали его: только диапазон (стартовые границы: 0, 1–5, 6–10, 11–20, 21–30, 31+, уточним);
- взаимные выборы не показываются вообще (как `░` в вашем отчёте);
- негативные выборы персонально не раскрываются;
- среднее по группе остаётся точным.

## 7. Отчёты

Личный (PDF, как ваш пример, 7 страниц): титул, пояснение терминов, 5 страниц критериев, итоговые показатели, интерпретация. Интерпретация генерируется шаблонами по порогам (сравнение со средним по группе), в конце приписка, что результат не оценка личности. В вашем образце есть ошибка вёрстки: «3130,00%» вместо «31,3»; в новой версии исправляем.
Рассылка: аналитик проверяет и нажимает «сформировать и отправить», PDF уходит на почту каждого. Ручная выдача по запросу остаётся.

Общий (безличный, для студсовета): индексы Gg, Ag, Y, U по критериям; социограммы по критериям (круг пропорционален статусу, стрелки это взаимные выборы); динамика по периодам; сводка по частным вопросам. Аналитик пишет текст отчёта в редакторе на сайте (формат Markdown), цифры и графики подставляются автоматически.

Новички и опытные на социограммах: по дате вступления `joined_at`. Её пока нет: добавим, когда подключится таблица с ФИО и датами. Окраска по объединениям не нужна (была разовой).

## 8. API и страницы (v1)

Участник
- `POST /register` (почта + ФИО)
- `GET /survey/current`, `PUT /survey/answers/{question_id}`, `POST /survey/submit`
- `GET /members?q=` поиск по ФИ, с признаком «серый»

Руководство
- `GET /completion` кто прошёл / не прошёл
- `POST/PUT /questions` создание частных вопросов, `GET /custom-answers`

Аналитик
- периоды: создание, открытие, закрытие
- `GET /analyst/answers`, `GET /analyst/flags`, исключение ответа
- `POST /analyst/compute`, `GET /analyst/stats`
- `POST /analyst/reports/personal/send`, `PUT /analyst/reports/group/{period}`

Публика
- `GET /reports/group/{period}`

## 9. Структура проекта

```
app/
  main.py
  config.py            # почты ролей, SMTP, пути к JSON
  models/              # Pydantic-модели
  storage/             # Repository + JSON-реализация
  services/            # опрос, валидация, расчёт, отчёты, почта
  routers/             # participant, management, analyst, public
  templates/           # Jinja: форма опроса, аналитик
  reports/             # PDF-шаблон, интерпретации
  seed/questions.json  # 9 постоянных вопросов
tests/
```
Инструменты: FastAPI, Pydantic, Jinja2, networkx + matplotlib для социограмм, PDF из HTML (Chromium/Playwright; на Windows проще, чем WeasyPrint), SMTP через стандартную библиотеку.

## 10. Порядок работ

1. Модели, JSON-хранилище, сид 9 вопросов.
2. Регистрация и опрос с серверной валидацией (серые карточки, флаги).
3. Расчёт индексов, тесты на цифрах из PDF (S 0,42, E 0,54, Gg 27,4%).
4. Личный отчёт в PDF и шаблоны интерпретации.
5. Страницы руководства и аналитика, рассылка.
6. Общий отчёт: индексы, социограммы, динамика, текст.
7. Потом: таблица мероприятий (отдельный доступ), шифрование, нейросетевая интерпретация, нормальный фронт.

## 11. Принятые риски и допущения

- Регистрация без подтверждения почты: любой может ввести чужие почту и ФИО и ответить за человека. Принято на доверии.
- Анонимность условна: при 60 людях по индексам можно догадаться об авторе, поэтому диапазоны и скрытая взаимность. Аналитик технически видит всё.
- Пока нет шифрования и контроля версий данных, нужна ручная копия файлов JSON перед каждым периодом.
